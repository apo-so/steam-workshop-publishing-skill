# 通用发布流程（不依赖具体游戏）

## A. 准备信息与证据

| 信息 | 核查方式 |
|---|---|
| 游戏 / AppID / 渠道 | 游戏官方页面与当前入口；区分消费内容的游戏 AppID 与制作工具 AppID |
| 初发 / 更新 | 初发检查是否已有对应条目；更新以条目 URL 的 `id`、本地绑定和平台显示的所属游戏与权限交叉确认 |
| Mod 版本 / 游戏兼容版本 | 区分作者版本号、元数据声明、实际测试版本；记录证据日期，不因元数据写了版本就承诺兼容 |
| DLC / 前置 Mod / 加载顺序 | 依实际引用、测试及作者明确提供的事实；无法证实则不作肯定声明 |
| 变更字段 | 列出旧值、新值、保留项、清除项（必须明确授权）、更新说明、目标可见性 |

更新时保存当前条目文案、主图、画廊、标签、依赖和可见性的可审阅快照；若不能读取就不要盲改。初发也要保存收到的条目 ID，不能用相似名称猜测目标。

## B. 正文和图片

正文建议按玩家实际使用顺序组织：有什么变化、如何使用、已验证的兼容性与依赖、重要限制、更新说明。只保留有用的信息；不凭空写评价、测试结论或不存在的功能。不同语言版本分别检查实际提交字段。参考 Steam [格式帮助](https://steamcommunity.com/comment/ForumTopic/formattinghelp)，具体 Workshop 编辑器支持情况仍须现场确认。

1. 保存最终 BBCode 原稿；HTML 由该稿生成，禁止在 HTML 里直接补发布正文。离线预览可用固定宽度模拟手机、桌面再人工检查；不能替代平台最终渲染。未知标签、远程图片和平台自动嵌入需显式待核，不能静默丢掉。
2. 字节统计使用实际拟提交文本的 UTF-8 编码；若输入文件以 UTF-8 BOM 起始，仅剥离这一文件标记，不改正文中的其他字符。不 `.strip()`、不统一 CRLF/LF、不删末尾换行，不做 Unicode 规范化。计数包含链接地址及全部 BBCode 字符。复制粘贴或工具转换导致变化时，对最终字段重新核算。官方 8000 字节上限，技能默认 7800 字节预算；不是网页必然接受的保证。达到 8000 边界仍保守退回修订，不假定终止符或前端实现细节。
3. 母图保存高质量版本，另导出发布缩略图；两者不可互相覆盖。按具体入口核查编码、尺寸与体积，API 预览预算严格小于 1000000 字节（见 [证据](sources.md)）。缩略图以缩小后能识别为目标；画廊按玩家动线从入口、核心功能、结果到特殊情形排序，逐张放大检查文字和界面，逐张上传及回读时确认顺序。文件扩展名不是编码证明，使用图片解码器验证实际格式和像素大小。网页画廊大小、格式、数量限制现场查，不把 API 限制推给网页。1000000 字节也可作为网页图片的自愿优化目标，但不能据此宣告网站必然拒收。
4. 本地审稿截图和长图仅用于审核；发布清单要显式选择主图及每张画廊图，未选择的不上传。清除图片中不应公开的个人资料和信息，检查来源及使用权。离线链接可检查语法和目标列表；在线检查链接有效性、权限、内容与预期目标后再报告结果。

## C. 内容包与连接条件

发布目录只放游戏运行所需内容以及受支持的发布元数据/缩略图。准备目录、源码历史（若不属于发布内容）、原始素材、测试日志、审稿 HTML/长图、环境配置、账号数据、开发缓存、秘密文件均放在发布目录外。以清单复核隐藏文件、符号链接/目录跳转、文本配置中的本机绝对路径和密钥；不确定的文件人工审阅，不靠文件名黑名单宣告无秘密。记录相对路径、SHA-256、字节数，核对授权后与提交前是否变化。备份现有元数据及绑定。不要将交付 ZIP 当作各游戏的通用上传格式；Steamworks 内容接口以目录为对象，按游戏入口的要求准备。

对采用客户端/启动器的上传入口，核对本机 Steam 客户端已运行、用户已登录且有写权限、在线模式、游戏许可及适用上传入口。实际可访问 Steam 社区和上传服务（社区主页可打开不等于上传服务已验证）；不进行试提交来探测。不能验证上传服务就记待核，不是假装联网成功。其他渠道按其官方文档独立确认。

即使在线、能玩该游戏且已登录，Steam 受限账户也不能向工坊投稿。让用户按 [Steam 受限账户说明](https://help.steampowered.com/en/faqs/view/71d3-35c2-ad96-aa3a) 自查；游戏礼物或零售激活密钥本身不解除限制。无需为检查而购买或充值，限制未解除时仍可离线准备。

断网、离线、DNS/网络故障或客户端未登录：暂停在线步骤，离线工作继续。先检查 Steam 状态、社区访问、服务状态、系统时间、合规网络配置与客户端错误提示；不要关安全防护或篡改证书来强行通过。普通直连正常即足够，无需加速器；确有连接问题且当地及平台规则允许时，用户可选择可信的网络加速服务，不能用于绕过封禁、地域限制、安全验证或权限控制。

## D. 展示与授权

展示发布预案：

- 游戏 / AppID / 渠道 / 初发或更新 / 已核 ID 或初发待生成。
- 本地版本和内容清单哈希、正文源哈希和实际字节数、媒体逐项哈希和顺序。
- 更新字段差异、保留/清除字段、可见性变更的影响、协议状态（用户本人确认）。
- 已完成的核查、仍需现场确认的事实、允许执行的具体下一步。

只有用户明确确认针对当前版本及目标的外部变更，且所有必需前提成立后，才能协助执行该动作。对创建、提交内容、网页保存、增删媒体、改可见性等分别界定授权；批量授权也必须逐项列明。条款接受、登录与二次验证不由代理执行。不具备动作工具时交给用户。修改了源或目标后，重新展示差异并确认。更新字段不在授权范围内就保持原值；若工具无法保证不覆盖其他字段，停止并改用受支持且可控的方式。

## E. 发布后证据（三层不可互相替代）

| 层级 | 需要记录的证据 | 常见未决 |
|---|---|---|
| 1 上传回执 | 渠道、时间、AppID、item ID、操作、状态/错误、上传内容清单 | 超时、无回执、仅进度完成、初发 ID 不明 |
| 2 页面回读 | 相同 ID / 游戏 / 标题、实际描述、主图/画廊顺序、依赖和可见性；必要时以授权范围内的非所有者访问方式核查可见性 | 缓存、仅所有者可见、协议未接受、审核/限制、媒体仍旧 |
| 3 订阅副本 | 已确认目标 ID；由用户以受支持方式下载或刷新后验证实际加载位置、版本标识与关键文件哈希，必要时独立测试环境验证 | 旧缓存、本地开发版覆盖、下载未完成、无可用测试账号 |

首次投稿可能需要用户验证注册邮箱；部分社区中心也会在公示前审核新条目或更新。作者自己看得到不代表已公开，订阅者也可能仍收到上一个核准版本。若已有 ID，保留 ID，先查看原条目状态并按 [Steam 投稿审核说明](https://help.steampowered.com/en/wizard/HelpWithUGCSubmission) 处理，不能因待审而再建一项。邮箱验证、工坊协议和可见性分开记录。

没有某层证据就标待核或异常。重复提交前按 ID 回查远端状态，结合回执和订阅结果再决定；首次创建无 ID 时先找已创建项，不能排除重复就停止。不要为测试擅自订阅、取消订阅、删除文件或改变可见性。
